# 债券交易询价语料 NER 需求文档

## 1. 项目背景

在债券交易中，交易员通过自然语言聊天的方式进行询价。询价语料中包含若干关键交易要素，但语料格式不固定，存在省略、连写、无关内容等情况。本项目旨在对用户输入的语料进行命名实体识别（NER），提取出预定义的 6 类关键交易要素。

## 2. 输入与输出

- **输入**：用户询价语料（字符串，自然语言）
- **输出**：识别出的要素列表，每个要素为 `(tag, text)` 对  
  - `tag`：要素类型
  - `text`：原始文本中对应片段的字符串

## 3. 要素定义

共 6 类要素，其中 **side** 和 **product** 为必填项，其余为可选项。

| Tag | 中文名称 | 是否必填 |
|-----|----------|----------|
| side | 交易方向 | 是 |
| product | 交易券码 | 是 |
| yield | 收益率 | 否 |
| quantity | 交易数量 | 否 |
| date | 清算日期 | 否 |
| speed | 清算速度 | 否 |

## 4. 各要素取值规范

### 4.1 side（交易方向）

固定值集（共 11 个）：

```
bid, ofr, buy, sell, offer, 买, 卖, 出, 收, 买入, 卖出
```

> 说明：无需考虑大小写，所有内容都为小写。

### 4.2 product（交易券码）

- 格式：6–10 位数字
- 可选后缀：`.ib`（如 `220495.ib`）
- 示例：
  - `223451`
  - `2600031`
  - `220495.ib`

### 4.3 yield（收益率）

- 数值类型：小数
- 小数位数：1–4 位
- 可选后缀：`%`
- 示例：
  - `2.0`
  - `1.78%`
  - `3.453`

### 4.4 quantity（交易数量）

**单位映射表：**

| 写法 | 含义 | 默认单位情况 |
|-----|----|----------------|
| e / 亿 | 亿  | —— |
| kw | 千万 | —— |
| w / 万 | 万  | —— |
| m / mio / million | 百万 | —— |
| 无单位 | 万  | 数字后无单位时默认单位是“万” |

**数值形式：**
- 整数或小数
- 示例：
  - `2.8e`
  - `3.5亿`
  - `5kw`
  - `3500w`
  - `4000`（默认万）
  - `235m`
  - `20mio`

> 注意：不要求统一单位，只需正确识别 `(tag, text)` 片段。

### 4.5 date（清算日期）与 speed（清算速度）

这两个要素绝大多数情况下**连写**，但也允许单独出现。

#### 连写模式

格式：`<date><speed>`

- **date 可选值**：
  ```
  t, tom, 今, 明, 今天, 明天, 今日, 明日, 周一, 周二, 周三, 周四, 周五
  ```
- **speed 格式**：`+` 后跟一个数字（如 `+0`, `+1`, `+2`）

示例：
- `t+0`
- `tom+1`
- `今天+2`
- `明+0`
- `明日+1`

#### 单独出现情况

- 只有 date：`今天`、`t`
- 只有 speed：`+1`、`+2`

> 标注要求：**date 和 speed 作为两个独立 tag**，即便是连写形式，也应拆分为两个实体（`date` 和 `speed`）。

## 5. 语料特点与难点

### 5.1 要素顺序
- 顺序不固定，可任意排列。

### 5.2 分隔方式
- 多数情况下各要素之间由空格分隔。
- 存在**连写**情况（尤其 quantity 与 side/product 等）。

可能会发生的连写示例：
- `bid2000w` → side: bid, quantity: 2000w
- `tom+1` → date: tom, speed: +1
- `明天买` → date: 明天, side: 买
- `5e收` → side: 收, quantity: 5e
- `出220405` → side: 出, product: 220405

### 5.3 无关内容
可能存在但不限于：
- 债券简称（如“25特长国债06”、“23附息国债11”）
- 债券类型（如“信用债”、“国开债”）
- 称呼（如“王总”）
- 语气词（如“早”、“您好”、“请问”）
- 债券剩余期限（如“7.62Y”、“345D”）等描述

这些内容不应被识别为 6 类要素之一。

## 6. 正确与错误示例（关键）

### 正确识别示例

| 输入语料 | 期望识别结果 |
|----------|----------------|
| 买 220495 2.3% 4000w t+0 | side:买, product:220495, yield:2.3%, quantity:4000w, date:t, speed:+0 |
| bid223451 1.78 3.5亿 tom+1 | side:bid, product:223451, yield:1.78, quantity:3.5亿, date:tom, speed:+1 |
| 出 2600031.ib 2.0 5kw | side:出, product:2600031.ib, yield:2.0, quantity:5kw |
| 收 220495 3.45% | side:收, product:220495, yield:3.45% |
| 买券 4000 | side:买, quantity:4000（无单位默认万） |

### 错误情况示例（不应识别）

- “王总您好” → 无任何要素
- “这只债剩余期限2.1年” → 不含交易要素

## 7. 标注与输出格式要求

最终输出为 JSON 或列表结构（由实现决定），推荐格式：

```json
[
  {"tag": "side", "text": "bid"},
  {"tag": "product", "text": "220495"},
  {"tag": "yield", "text": "2.3%"},
  {"tag": "quantity", "text": "4000w"},
  {"tag": "date", "text": "t"},
  {"tag": "speed", "text": "+0"}
]
```

## 8. 验收标准

1. 正确识别语料中出现的各要素。
2. 能够处理**连写**（如 `bid2000w`）、**省略单位**、**带/不带 %** 、**带/不带 .ib** 等情况。
3. 能够从包含无关内容的完整句子中仅提取目标要素。
4. 连写的 `date+speed` 必须分开标记为两个独立实体。
